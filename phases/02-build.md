## Build and verify

Implement the approved atlas as a persistent web service. Replace fictional content, preserve real approval provenance, and connect a real authorized executor. Build the contextual nudge flow, durable dispatch, context manifests, version checks, result reporting, and recovery. The Director sees the current phase, leading baseline, and the basis and boundaries of each assignment.

Use the full acceptance suite to plan verification and record actual outcomes. A browser preview and passing demo unit tests alone do not qualify. Missing credentials or unavailable execution may block affected acceptance; continue useful independent work without claiming handover.

If scope materially changes, hold affected work and obtain approval of the revised baseline. Load only the relevant concept guidance for that assessment. Preserve unaffected valid approvals and historical results.

## Transition condition

All applicable mandatory acceptance scenarios, including real activation and context delivery, pass with revision-bound evidence. The approved baseline and original decisions are verified in the service. The Director explicitly accepts operational handover, with any agreed limitations recorded; limitations cannot waive mandatory real-execution or authorization criteria.

Persist the handover evidence, Director acceptance, phase transition, and next phase path in the atlas. Only then read [Phase 3: Operate and iterate](03-operate.md). Until then, remain in build or handover validation.
