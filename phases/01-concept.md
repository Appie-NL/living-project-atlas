# Phase 1: Develop the Concept

Entry: a new project, or a resumed project whose phase needs reconstruction. Keep the fixed rules from [START.md](../START.md) active. Do not reload it if already present.

## Read now

Read [CONCEPT.md](../CONCEPT.md) completely. Its descriptions of later stages explain the intended outcome; their links are not required reading during this phase. Do not load PROMPT.md, architecture, the full activation contract, template source, or acceptance suite yet.

Use the Director's brief and relevant existing project facts to establish purpose, users, constraints, alternatives, risks, scope, and observable success. Research concrete uncertainties with scoped searches. Load other method references only if needed to resolve a specific concept question, recording the reason; this never authorizes a phase transition.

The eventual atlas must let the Director initiate analysis and authorized work from tasks and decisions, receive real agent feedback, and review evidence. Include that outcome in the concept and bounded build scope. Do not implement the runner or atlas during concept development.

The Director may preview the unchanged fictional template. If requested, read only the run instructions in `template/README.md` and the minimum files needed to resolve a preview problem. Previewing is not concept approval or a reason to study all implementation files.

## Persist before leaving

Maintain the versioned concept baseline, research rationale, material open questions, proposed atlas structure, bounded build scope, and the current context record described in START.md. Include the actual Director response and its source, baseline version, scope limits, and time; mark absent approval honestly.

## Transition condition

The Director has explicitly approved this baseline and the bounded atlas build. Resolve approval-relevant contradictions first. Neither a request to start the project nor approval of a research experiment meets this condition. While waiting, continue only authorized concept work.

Only after recording that approval and the phase transition, read [Phase 2: Build and hand over](02-build.md). The next phase checks technical readiness before construction starts. Material changes to the baseline require renewed approval for the affected scope, not repetition of unchanged approvals.
